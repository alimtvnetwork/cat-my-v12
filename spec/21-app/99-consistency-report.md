# 99 — Consistency Report Contract

**Status:** Locked (Plan 04 Step 46). Defines the machine + human check that verifies spec, code, and project memory stay in sync. Referenced by acceptance gate A-22.

Anchors: 00 (authoring rules), 26 (migrations), 40–45 (cross-cutting), 46 (open questions), 97 (acceptance), 98 (changelog).

## 1. Purpose

The consistency report is the single artifact that answers: "Does the spec, the code, and the memory tell the same story right now?" It runs on every release-candidate build and its output is the evidence for A-22.

## 2. Inputs

The report ingests, in this order:

1. All files under `spec/21-app/*.md` (contracts).
2. All files under `.lovable/memory/*.md` (rules the agent applies).
3. Source tree under `src/**` and any worker binary manifests.
4. `changelog.md` and `release_notes.md` top blocks.
5. Root `readme.md` version line.

Missing any input is `E_CONSISTENCY_INPUT_MISSING`.

## 3. Required Checks

Each check emits a `PASS` or a typed `E_*` code with the offending path.

### 3.1 Anchor integrity

- Every `E_*` code referenced in spec or memory is defined in exactly one section.
- Every `Q-<NN>` and `A-<NN>` ID resolves to a section in 46 or 97.
- Every spec cross-reference points at an existing section number.
- Failure: `E_CONSISTENCY_DANGLING_REF`.

### 3.2 Contract ↔ code parity

- Types referenced by locked contracts (32 shape model, 33 rule catalog, 34 tolerance, 36 instruction bundle, 40 error taxonomy) exist in source with matching names and PascalCase.
- Field names in JSON contracts match declared casing.
- Failure: `E_CONSISTENCY_CONTRACT_DRIFT`.

### 3.3 Memory ↔ spec parity

- Every rule in `.lovable/memory/**` cites a spec anchor or is marked project-meta.
- No memory rule contradicts a spec section (e.g. palette hex vs 04-design-system).
- Failure: `E_CONSISTENCY_MEMORY_DRIFT`.

### 3.4 Changelog ↔ spec parity

- Latest `changelog.md` version equals `readme.md` pinned version equals top `release_notes.md` version.
- Every bullet in the latest CHANGELOG block cites an anchor per 98 §3.
- Failure: `E_CONSISTENCY_CHANGELOG_DRIFT`.

### 3.5 Open-questions ↔ resolution log

- Every `Q-<NN>` moved out of `BLOCKS_V1` has a matching entry in 46 §5 AND an anchor edit in the referenced changelog version.
- Failure: `E_CONSISTENCY_QUESTION_UNCLOSED`.

### 3.6 Acceptance signal presence

- Each gate signal named in 97 §2–§6 is either implemented (test/metric exists) or explicitly marked `PENDING <plan-step>`.
- Failure: `E_CONSISTENCY_GATE_SIGNAL_MISSING`.

### 3.7 Prompt registry currency

- `.lovable/prompt.md` `next task` alias points at the highest-numbered `NN-next-task.md` file that exists.
- Failure: `E_CONSISTENCY_PROMPT_ALIAS_STALE`.

## 4. Output Shape

The report is a single Markdown file under `spec/25-app-audit/consistency-<version>.md` with sections:

```
# Consistency Report — v<version> — <YYYY-MM-DD>

## Summary
Total checks: N. Pass: N. Fail: N.

## Failures
- <E_CODE> — <path> — <one-line description>

## Notes
- <PENDING items and their tracking plan step>
```

An empty `## Failures` block is required for A-22 to pass.

## 5. Cadence

- Run on every version bump per 98 §6.
- Run in CI on PRs that touch `spec/**`, `.lovable/memory/**`, or the source files backing a locked contract.
- Manual-only invocation is allowed for exploration; result is not evidence.

## 6. Governance

- The report is generated, not hand-written; hand edits are `E_CONSISTENCY_REPORT_TAMPERED`.
- A green report is required, not sufficient — human review still applies for semantic drift the checker cannot see.
- Suppressing a check is `E_CONSISTENCY_SUPPRESSED`; only 46 §4 out-of-scope entries may reduce a check to `N/A`.

## 7. Failure Modes

- `E_CONSISTENCY_INPUT_MISSING`
- `E_CONSISTENCY_DANGLING_REF`
- `E_CONSISTENCY_CONTRACT_DRIFT`
- `E_CONSISTENCY_MEMORY_DRIFT`
- `E_CONSISTENCY_CHANGELOG_DRIFT`
- `E_CONSISTENCY_QUESTION_UNCLOSED`
- `E_CONSISTENCY_GATE_SIGNAL_MISSING`
- `E_CONSISTENCY_PROMPT_ALIAS_STALE`
- `E_CONSISTENCY_REPORT_TAMPERED`
- `E_CONSISTENCY_SUPPRESSED`

## 8. Non-Goals

- Does not lint prose style.
- Does not judge design quality — only contract sync.
- Does not replace tests in 45 — it verifies they exist, not that they are correct.
