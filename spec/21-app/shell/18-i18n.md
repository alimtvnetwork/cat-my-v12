# Internationalization

Status: Draft (Plan 28)

## Locale resolution

1. Renderer reads OS locale via shell (Tauri `os.locale`).
2. User override in `settings.locale` persists to `<data-dir>/permissions.json`
   (misnomer — split to `settings.json` in a later migration).
3. Renderer loads bundle from `dist/locales/<locale>.json`; missing keys fall
   back to `en`.

## Supported locales (v1)

- `en` (source of truth)
- `de`
- `zh-Hans`

Add locales by dropping a JSON bundle plus updating `settings.locale` options.

## Right-to-left

- CSS uses logical properties (`margin-inline-start`, `padding-block-end`).
- `<html dir="rtl">` set when locale is RTL.
- Icons that indicate direction (arrows) mirror via CSS.

## Content rules

- No concatenated strings — every phrase is one key.
- Dates via `Intl.DateTimeFormat`; numbers via `Intl.NumberFormat`.
- Server-side error messages (`hint` in IPC error envelope) are also localised
  server-side keyed off `Accept-Language`.
