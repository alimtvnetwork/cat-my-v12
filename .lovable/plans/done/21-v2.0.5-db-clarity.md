# Plan 21 - v2.0.5 DB Clarity (Audit Persistence)

Status: pending (scoping landed at v2.29.0)
Owner: Lovable agent
Predecessor: Plan 20 (v2.0.4 audit retention, done)
Successor: Plan 22 (v2.0.6 Design polish)

## Root cause we prevent going forward

`getAuditRetentionStatus` and `exportAuditBundle` both return deterministic empty snapshots because the `audit_events` persistence layer does not exist. Without a locked schema, indexes, and a Python sink, the `/ops` retention tile can never show real `oldestSurvivingTs` / `rowsPurgedLast24h`, and `exportAuditBundle` can never emit `AuditBundleExported` with real byte counts. Every subsequent v2 feature (rule bundle import audit, catalog admin audit, license activation audit) would ship without a validated storage path.

## Scope

1. Lock `audit_events` schema in spec 72 (columns, types, constraints).
2. Lock covering indexes for the retention worker query planner and the export sort `(ts ASC, eventId ASC)`.
3. Supabase migration for `public.audit_events` with GRANTs, RLS (`has_role(auth.uid(), 'admin')` SELECT only; service_role INSERT), and admin read policy.
4. Python sink adapter (`app/core/audit/sink_sqlite.py`) writing `audit_events` rows with the exact column set; retention worker rewired to query counts.
5. Wire `getAuditRetentionStatus` to real counters (via server fn hitting `supabaseAdmin` under admin check).
6. Wire `exportAuditBundle` to physical `.catauditjsonl` writer: stream rows in `(ts ASC, eventId ASC)` order, chunk to 4 MiB, enforce `E_AUDIT_EXPORT_SIZE_CAP` at 256 MiB, compute payload sha256, emit `AuditBundleExported` with real bytes / count / sha.
7. Sink self-test on boot (`E_AUDIT_SINK_UNAVAILABLE`).
8. Migration verification: apply migration in test project, verify grants + RLS + index plan.
9. Unit tests: schema round-trip, retention counter accuracy, exporter byte cap, checksum stability.
10. Close-out: pin v2.0.5, archive Plan 21, evidence bundle, README/CHANGELOG/RELEASE_NOTES update, next-task prompt.

## Non-goals
