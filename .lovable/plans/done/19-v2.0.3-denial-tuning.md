# Plan 19 - v2.0.3 Denial-Burst Tuning

Status: completed
Owner: v2.0.3 track (per `spec/21-app/62-v2-execution-order.md:44-52`)
Baseline: Control Automation v2.12.0 (v2.0.2 pinned 2026-07-14, Plan 17 archived)
Depends on: v2.0.1 admin-write path (`I_SEC_ADMIN_WRITE`), `DenialRateLimiter` seat at `app/core/config/settings_store.py:33,75,197`

## Goal

Ship v2.0.3: make `DenialRateLimiter` thresholds admin-writable through `SettingsStore` and derive the shipped defaults from real `/ops` denial telemetry over the prior 24h window (not guessed). Threshold changes take effect on the next request without a process restart.

## Exit criteria (verbatim from execution order)

1. Rate limiter thresholds live in `SettingsStore` (already true: `SECURITY_DEFAULTS` + `apply_security_settings`) and are admin-writable via `I_SEC_ADMIN_WRITE`.
2. Defaults derived from `/ops` denial telemetry over the prior 24h window (documented derivation).
3. Non-admin write denied with `E_SEC_DENIED`.
4. Tests: threshold change is honored on the next request without process restart; burst above threshold produces `E_SEC_DENIAL_BURST` (surfaced as `CODE_RATE_LIMITED = E_SEC_RATE_LIMITED`).

## Steps

1. Baseline snapshot: version, head, `python3 -m pytest tests -q` count -> `.lovable/memory/v2/plan19/00-baseline.md`.
2. Author `spec/21-app/69-v2-denial-tuning-contract.md`: lock the `security` section schema (`denial_threshold: int >= 1`, `denial_window_seconds: int >= 1`), the admin-write path, the derivation rule for defaults (24h `/ops` telemetry sample), and the `E_SEC_*` taxonomy (`E_SEC_DENIED` for non-admin, `E_SEC_RATE_LIMITED` for burst refusal, `E_SEC_DENIAL_BURST` as the audit code emitted when a burst trips).
3. Telemetry query: add a read-only helper `derive_denial_defaults(audit_sink, window_hours=24)` that reads `/ops` audit rows for `CODE_ROLE_DENIED`/`CODE_NOT_AUTHENTICATED`, returns `{denial_threshold, denial_window_seconds, sample_size, derivation}`. NEVER writes.
4. Wire admin-write path: extend `SettingsStore.write_section("security", ...)` validation to reject non-positive ints with `E_CFG_INVALID_SECURITY` and to call `apply_security_settings` on commit so the live limiter retunes in-process.
5. Emit `I_SEC_ADMIN_WRITE` with `subject="settings.security.denial"`, prior/next JSON payloads. Non-admin path already denies via existing role check - add a unit test that pins that path to `E_SEC_DENIED`.
6. Audit code: introduce `CODE_DENIAL_BURST = "E_SEC_DENIAL_BURST"` in `app/core/security/audit_sink.py` and emit it once per burst trip (dedupe by (user_id, window_start)) so we do not spam the audit log per request.
7. Unit tests:
   - `tests/unit/test_denial_tuning_admin_write.py`: admin write succeeds, emits `I_SEC_ADMIN_WRITE`, limiter retunes; non-admin write raises `E_SEC_DENIED`; invalid ints raise `E_CFG_INVALID_SECURITY`.
   - `tests/unit/test_denial_tuning_hot_reload.py`: write new threshold, next request over the new limit trips `RateLimitedError(E_SEC_RATE_LIMITED)`, and the audit log records exactly one `E_SEC_DENIAL_BURST`.
   - `tests/unit/test_denial_defaults_derivation.py`: seed audit sink with 24h of denial rows, assert `derive_denial_defaults` returns thresholds within documented bounds and reports `sample_size`.
8. Ops UI: `/ops` denial-telemetry panel (read-only) surfaces current threshold + window + last derivation timestamp. No admin controls in UI for v2.0.3 (CLI/server-fn only) - documented deferral.
9. Evidence bundle `.lovable/memory/v2/plan19/40-evidence.md`: map each exit criterion to file+line, paste pytest output, link the derivation memo.
10. Bump to v2.0.3, update README banner / CHANGELOG / RELEASE_NOTES, archive this plan to `.lovable/plans/done/19-v2.0.3-denial-tuning.md` with `Status: completed`.
