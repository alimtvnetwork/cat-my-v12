## Context

`spec/21-app/62-v2-execution-order.md:44-52` locks v2.0.2 exit criteria: full `open()->grab()->close()` round-trip per vendor, `>=77 fps` sustained for 60s in `app/capture/perf_harness.py`, `VendorDeviceIO` buffer-ownership contract (no vendor-thread refs after `release`), `E_CAP_*` failure taxonomy with no raw vendor exceptions leaking, and one perf JSON artifact per vendor linked from release notes.

Adapters land at `app/capture/pylon_device_io.py:114`, `spinnaker_device_io.py:175`, `vimba_device_io.py:158`; wrapper at `app/capture/vendor_device_io.py` already normalizes `HardwareTimeoutError` / `DeviceDisconnectedError`. v2.0.2 must extend that normalization to the full `E_CAP_*` taxonomy and add a hardware acceptance harness gated behind an env flag so CI (hardware-absent) stays green.

## Steps

1. Snapshot baseline: version, head, `python3 -m pytest tests -q` green count -> `.lovable/memory/v2/plan17/00-baseline.md`.
2. Author `spec/21-app/68-v2-vendor-sdk-contract.md`: lifecycle state machine (`Closed -> Opening -> Open -> Grabbing -> Open -> Closing -> Closed`), buffer-ownership rule (caller owns bytes after `grab`; adapter MUST NOT retain vendor-thread refs after `close`), and the full `E_CAP_*` taxonomy (`E_CAP_SDK_ABSENT`, `E_CAP_OPEN_FAILED`, `E_CAP_GRAB_TIMEOUT`, `E_CAP_DISCONNECTED`, `E_CAP_BUFFER_LEAK`, `E_CAP_ENUM_FAILED`, `E_CAP_UNKNOWN`).
3. Extend `app/capture/vendor_device_io.py` error normalization: every raised path maps to an `E_CAP_*` code carried on a `CaptureAdapterError(code, vendor, detail)`; no raw vendor exception escapes. Add structured log line `vendor_io.<op> code=E_CAP_* vendor=<v>`.
4. Pylon adapter (`pylon_device_io.py:114`): wire `open/grab/close` to real `pypylon` calls under `try: import pypylon` guard; SDK-absent path returns the `E_CAP_SDK_ABSENT` adapter (already covered by v2.0.1 discovery E1). Buffer copy on `RetrieveResult` before releasing grab result.
5. Spinnaker adapter (`spinnaker_device_io.py:175`): same shape via `PySpin`; guarantee `image.Release()` in a `finally` after copying bytes; `NodeMap` cleanup in `close()`.
6. Vimba adapter (`vimba_device_io.py:158`): same shape via `vmbpy`; frame handoff MUST copy `frame.as_numpy_ndarray().tobytes()` before `queue_frame` returns.
7. Perf harness (`app/capture/perf_harness.py`): add `--vendor {pylon,spinnaker,vimba}` CLI, run 60s grab loop, emit JSON `{vendor, fps_mean, fps_p05, dropped_frames, duration_s}` to `tests/reports/perf-<vendor>.json`. Fail non-zero if `fps_p05 < 77` or `dropped_frames > 0`.
8. Add `HARDWARE_ACCEPTANCE=1` env gate: without it, harness prints `skipped: HARDWARE_ACCEPTANCE unset` and exits 0 so CI stays green.
9. Unit tests (CI-safe, mocked SDK): `tests/unit/test_vendor_sdk_error_mapping.py` covers each `E_CAP_*` mapping in `vendor_device_io.py` via injected fake SDKs. `tests/unit/test_vendor_buffer_ownership.py` asserts `grab()` returns a fresh `bytes` object (not aliased to any SDK-owned buffer) for all three adapters.
10. Hardware acceptance run (deferred to on-site harness): capture `perf-pylon.json`, `perf-spinnaker.json`, `perf-vimba.json` under `.lovable/memory/v2/plan17/artifacts/`. Record `Skipped` in evidence when hardware absent; do NOT fake numbers.
11. Evidence bundle `.lovable/memory/v2/plan17/40-evidence.md`: unit test output, harness invocation, per-vendor artifact links, and explicit hardware-status row (`Skipped` vs `Passed`).
12. Bump to v2.0.2, update README banner + CHANGELOG + RELEASE_NOTES, archive this plan to `.lovable/plans/done/17-v2.0.2-vendor-sdk.md` with `Status: completed`.
